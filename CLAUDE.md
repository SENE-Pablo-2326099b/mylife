# MyPerf — notes projet

- Contexte complet de l'écosystème MyLife (MyFinances + MyPerf) : `CONTEXTE.md`.
- UI en français. Thèmes : `src/ui/themes.ts` (8 palettes Lumen, Nuit sombre par défaut, chaque palette a un équivalent clair/sombre pour « Suivre le téléphone » ; + 4 identités Circuit / Ardoise / Argile / Brut qui changent aussi formes, polices et matière : `stylize`, `applyIdentity`, `Glass`, `Backdrop`), réglages `theme` (ThemeId) + `followSystem`. Jamais de couleur littérale dans un écran : un jeton de `Palette` (en ajouter un dans `theme.ts` + les deux constructeurs de `themes.ts` si besoin) ; contrastes testés par `src/ui/__tests__/themes-test.ts`. Voir README.md pour l'architecture et les décisions métier.
- Ergonomie (cf. ERGONOMIE.md) : l'essentiel visible, le rare à un tap (`Disclosure`, `Sheet`, écran de détail) ; action principale des écrans d'édition dans `Screen footer` ; options rares d'une série dans la feuille `SetNoteSheet` (toucher le numéro), pas sur la ligne ; en séance seul l'exercice en cours est déplié.
- Couches : `src/domain` pur (testé), `src/db` (SQL synchrone, migrations append-only dans `migrations.ts`), `src/services`, `src/state`, `src/features`, `src/ui`, `src/app` (routes).
- Toute écriture passe par `db()` (src/db/db.ts) qui incrémente une version ; les écrans lisent via `useLive` (re-requête seulement si l'écran a le focus).
- `useLive` porte `'use no memo'` : il lit la DB pendant le rendu, le React Compiler ne doit pas mémoïser l'appel.
- Nouvelle colonne/table → nouvelle migration + mise à jour de `TABLES` dans `src/db/backup.ts`.
- Vérifier avant de conclure : `npx tsc --noEmit`, `npx expo lint`, `npm test`.
- Aperçu web : driver `src/db/expoDriver.web.ts` (sql.js). Si Metro ne voit pas un nouveau fichier, relancer avec `--clear`.
- Programme réel : `data/programme-reel.md` prime sur le carnet Excel. Transcription dans `src/import/personalProgram.ts` ; CSV embarqué par `npm run gen:import` (ne pas éditer `historyCsv.ts` à la main).
- e1RM et % des exercices lestés : toujours sur la masse totale (poids de corps + lest), règle du programme. Charges des lifts principaux = % du 1RM de référence : d'abord le 1RM saisi par l'utilisateur (`exercise_one_rm`, valeur telle que loggée = lest pour les lestés, + poids de corps de la séance ; `referenceFor`/`referenceInfo` dans workoutService, S4/test → simple proposition via `suggestManualUpdate`), sinon l'estimation (`src/domain/reference.ts` : séries ≤ 6 reps, provisoire sinon, calibration S4/Test plafonnée +2,5 %/cycle). S4 pré-remplie 1×2 @92,5 % (cycles restés sur l'ancienne 1×3 @88 % migrés une fois par `upgradeLegacyS4`). % affichés via `formatPercent` (92,5 %), steppers de % au pas de 2,5 avec `snap`. Chaque séance garde la référence utilisée (`workout_exercises.reference_e1rm`) pour lire les séries par rapport au plan. Règle de l'utilisateur : charge = % du jour × 1RM (± poids de corps), rien d'autre — ni la séance précédente, ni la vitesse de barre ; avec une référence, les backoffs ne suivent pas le top set en direct (`normalize` du workoutStore) et la colonne grise des séries affiche le % (`ExerciseItem.percents`) au lieu de « Préc. » ; un 1RM modifié recale les séries à faire de la séance en cours (`refreshActiveTargets`). Plus de charge imposée par semaine (`top_weight` ignorée, vidée par la migration 7) : les ajustements de semaine ne portent que sur séries/reps/%. Une séance planifiée démarrée un autre jour garde la semaine de cycle de son jour prévu (`startWorkout`, comme son aperçu) ; démarrer une séance type un jour où elle est planifiée la rattache à ce planning.
- Volume par muscle : bras (biceps, triceps, avant-bras) = isolations seulement en direct (et dans la cible), composés en `indirect` affiché à part (`isIndirect`, src/domain/analytics.ts ; `regionLoads` idem).
- Carnet : les commentaires (colonne I de SÉANCES) priment sur le nom de l'exo ; corrections dans `src/import/carnetCorrections.ts`. Toute évolution de l'import → incrémenter `PERSONAL_IMPORT_VERSION` (l'upgrade reconstruit seulement l'historique importé).
- UI « Lumen » (Liquid Glass) : voir README § Interface. Écrans = `Screen` (+ `stack`/`modal`, `mood`) et primitives de `src/ui` ; pas de `Stack.Screen` d'en-tête (headerShown false partout, barres en verre maison).
- Reanimated : `.set()` sur les shared values hors worklets (lint React Compiler). Sur le web, les `entering/exiting/layout` laissent l'élément en `position: absolute` → passer par `flowAnim()` (désactivé sur web) ou un shared value (cf. `Reveal`).
- zustand : un sélecteur doit renvoyer une primitive ou passer par `useShallow`, sinon boucle de rendu (« getSnapshot should be cached »).
- Aperçu web pour vérifier l'UI : `npx expo start --web --port 8090` SANS `CI=1` (sinon Metro ne surveille plus les fichiers). Le port 8081 est pris par un autre projet.
- Responsive téléphone d'abord (app native verrouillée en portrait) : jamais plusieurs `Stepper` côte à côte à 3 (utiliser `StepperRow`), largeurs des rangées de série via `useSetMetrics()`, textes avec `numberOfLines`/`flexShrink` plutôt que largeurs fixes, plafond de police (`Text` 1.3×, chrome 1.15-1.2×). Vérifier sur la matrice 280→430 px de large et 568→932 px de haut (banc puppeteer, cf. mémoire web preview).
- Coach IA (`src/services/coach/`, écran `src/app/coach.tsx`) : API Claude via `@anthropic-ai/sdk`, `claude-sonnet-5-5` par défaut et `claude-opus-5-5` en « Analyse poussée » (`COACH_MODELS`), cache sur système + outils + dernier message, boucle d'outils manuelle ; ouvrable avec une question pré-remplie (`/coach?q=…`, jamais envoyée seule) ; outils de lecture libres, outils d'écriture = propositions validées par l'utilisateur. Historique append-only (blocs de réflexion renvoyés tels quels). Clé dans expo-secure-store (localStorage sur le web). `metro.config.js` force le build CommonJS du SDK (le build ESM casse sous Metro).
- Remplacement d'exercice en séance (`replaceExercise`, `SwapSheet`) = créneau fait avec un autre exercice : `workout_exercises.replaces_exercise_id` garde l'exercice prévu (migration 8), affiché « à la place de … » sur la carte ; chaque exercice garde sa propre progression. Le coach le reçoit (`replaces` dans get_recent_workouts, `replaced_on` dans get_exercise_history) et la règle du prompt lui interdit de le reprocher.
- Mésocycles typés (`src/domain/mesoTypes.ts` : accumulation / transmutation / realization / transition / custom) ; le type pré-remplit la structure. Notes par série : colonne `sets.note` (migration 5), feuille `SetNoteSheet`, appui long sur une série = menu (note / supprimer).
- Carte musculaire : `src/domain/bodyMap.ts` (régions ↔ muscles ↔ tracés), dessin = tracés de react-native-body-highlighter rendus par `features/exercises/BodyMap.tsx` (sur le web : `onClick` + `onPress: null`, sinon react-native-svg écrase le clic et injecte des props de responder dans le DOM).
- Perf Android (milieu de gamme) : pas de `boxShadow` brut, passer par `shade(css, repeated)` (src/ui/theme.ts : sur Android retire les ombres internes, et les lueurs des éléments répétés) ; `Glass` n'a d'ombre floue que pour `float`/`lens` ; halos du fond figés (texture GPU), `Reveal` et l'animation des onglets désactivés sur Android. APK local : `cd android && ANDROID_HOME=~/android-sdk ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a --max-workers=2` (à 4 ou sans limite, WSL tue la compilation faute de mémoire).
- Nombres affichés en français : `formatWeight` / `formatDecimal` (virgule décimale) ; `plainWeight` (point) pour les tampons du clavier et les données envoyées au coach. Jamais de `toFixed` brut dans l'UI.
- Date du jour dans les écrans à onglets : `useToday()` (suit le passage à minuit et le retour au premier plan), pas `today()` au rendu.
- Écran poussé dont l'enregistrement n'existe plus : `NotFoundScreen` (src/ui/components/Screen.tsx), jamais d'écran vide.
- Suppressions : toast « Annuler » plutôt que confirmation ; pour restaurer des lignes entières, `selectRaw` / `insertRaw` (src/db/raw.ts), cf. `deleteMesocycleUndoable`, `archiveTemplateUndoable`.
- Aperçu d'une séance type avant de la démarrer : `templatePreview()` (workoutService, même moteur que le démarrage) — c'est ce qu'affiche l'accueil.
- `Glass` accepte `pointerEvents="box-none"` jusqu'à sa couche de contenu ; la barre condensée de `Screen` ne prend les touchers qu'une fois visible (sinon elle masquait le bouton Coach IA).
