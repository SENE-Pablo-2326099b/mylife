# V2 : ce qui a changé, comment et pourquoi

La V1, « Budget Dodge », était un suivi de dépenses fait pour une seule personne. Elle est devenue **MyFinances** :
- une app de **gestion de finances complète** (budget, comptes, placements, objectifs, prévisions) ;
- **personnalisable par n'importe qui** ;
- habillée du design system **Lumen** de MyPerf.

La logique de la V1 n'a pas été réécrite. Le budget du jour, le cycle, les règles, la synchro Enable Banking, la déduplication et les alertes sont les mêmes fonctions qu'en V1 ; elles sont toujours testées.

Vérifié à la fin :
- `npm run typecheck`, `npm run lint` (0 erreur, 0 avertissement), `npm run build` ;
- `npm test` : **224 tests, 19 fichiers** (168 en V1) ;
- `npm run screenshots` : tous les écrans en thème **Nuit** (sombre) et **Perle** (clair), à **320, 390 et 430 px** de large, plus 1 280 px. Résultat : **aucune erreur console, aucun débordement horizontal**, et l'app se recharge hors ligne.

## 1. Le design system Lumen (repris de MyPerf)

**Pourquoi.** Tu voulais exactement l'identité de MyPerf : du verre flottant sur un champ de lumière.

**Comment.** J'ai lu le code source de MyPerfV2 (`src/ui/theme.ts`, `themes.ts`, `Glass.tsx`, `Backdrop.tsx`, `Screen.tsx`, `primitives.tsx`, `Sheet.tsx`, `charts.tsx`, la navigation, le test de contraste). Je l'ai porté de React Native vers le web en gardant **les mêmes valeurs** : couleurs, niveaux de verre, ressorts, tailles, rayons.

| Élément | Où | Détail |
|---|---|---|
| Jetons et thèmes | `src/ui/theme.ts`, `src/ui/themes.ts` | Palettes Nuit et Perle identiques à MyPerf. 6 autres thèmes (Océan, Braise, Graphite, Glacier, Sable, Craie) construits à partir d'une **graine** par les mêmes règles. Chaque thème a son équivalent clair/sombre. |
| Variables CSS | `cssVars()` + `ThemeProvider.tsx` | La palette est posée en variables CSS sur `<html>`. Tailwind ne connaît que ces jetons : **aucune couleur écrite en dur dans les écrans**. |
| Verre | `.glass`, `.glass-raised`, `.glass-float`, `.glass-lens` dans `index.css` | Chaque plaque a un remplissage translucide, un reflet en haut, un lavis de teinte (option), un bord fin, un liseré spéculaire (ombre interne d'1 px) et une ombre portée. Le vrai flou n'est utilisé que sur `float` et `lens`. Sur Android, ou sans `backdrop-filter`, le verre est plus dense et les ombres des éléments répétés sont retirées, comme dans MyPerf. |
| Fond animé | `src/ui/Backdrop.tsx` | Dégradé et 4 halos (violet, or, indigo, orchidée) qui dérivent lentement, avec une parallaxe au défilement. Chaque section a son **ambiance** : Aujourd'hui, Budget, Opérations, Patrimoine, Réglages, Focus. Les halos sont figés sur Android et quand on réduit les animations. |
| Typographie | `tailwind.config.js` (classes `t-hero` → `t-label`) | Sora 700/600 pour les titres et les chiffres (chiffres tabulaires), Inter pour l'interface. Polices **embarquées** (@fontsource) : aucun appel à Google Fonts. Grossissement du texte plafonné à ×1,3 (×1,2 pour les contrôles) avec `min(rem, px)`. |
| Mouvement | `src/ui/motion.ts` | Ressorts `snappy`, `soft` et `liquid` (mêmes constantes que MyPerf, via framer-motion). Retour haptique léger sur Android. Apparition échelonnée des blocs. Tout respecte « réduire les animations » (système et réglage dans l'app). |
| Composants | `src/ui/primitives.tsx`, `Screen.tsx`, `Navigation.tsx`, `Sheet.tsx`, `toastStore.ts`, `charts.tsx`, `extras.tsx` | Screen (grand titre avec sur-titre or, qui se condense en barre de verre), barre d'onglets flottante à **indicateur liquide** (deux bords sur deux ressorts), barre latérale au-delà de 1 024 px, Card, Group/Row, Button (primaire = lumière liquide, « magnétique » en grand format), IconButton, Chip, Badge, Segmented (pastille qui glisse), Toggle, Stepper, Field, Sheet (feuille « lens » qu'on jette vers le bas), Disclosure, EmptyState (orbe), Skeleton (balayage lumineux), Orb de validation, anneau de lumière, graphiques en SVG (faisceau or → violet, lavis dessous, réticule au toucher). |
| Suppressions | `toastStore.ts`, `db/undo.ts` | **Plus aucun `confirm()`.** Toute suppression montre un toast avec « Annuler » : règle, catégorie, ligne, objectif, placement, mouvement, versement, démo, « tout effacer », import de sauvegarde. Les actions irréversibles côté banque (déconnexion) sont **différées** jusqu'à la disparition du toast. |
| Graphiques | `src/ui/charts.tsx` | **Recharts a été retiré** : les courbes sont dessinées dans le style Lumen. Les couleurs de répartition suivent un ordre fixe, distinct de l'accent, avec un contraste vérifié par le test des thèmes. |

**Vérification des contrastes** (`tests/themes.test.ts`). Pour les 8 thèmes : texte ≥ 7:1, secondaire ≥ 4,5:1, discret ≥ 3:1, couleurs porteuses de sens ≥ 3:1 sur le fond.

**Sens des couleurs dans le budget :**
- **violet** : action principale, onglet et élément actifs ;
- **or** : objectifs atteints, objectif de catégorie tenu sur un cycle terminé, indépendance financière ;
- **vert** : revenus, « dans le budget » ;
- **orange** : presque atteint ;
- **rouge** : dépassement.

## 2. Pour tout le monde, tout personnalisable

**Pourquoi.** La V1 contenait tes données en dur : salaire de 1 537 €, APL, paie le 26, ton nom pour les virements, Lancelot, tes restos d'Aix, le pass Métropole…

**Comment :**
- **Accueil guidé au premier lancement** (`src/pages/Onboarding.tsx`) : prénom, jour de paie, revenus, charges fixes, épargne, nom sur les virements, thème. On peut tout passer et tout reste modifiable ensuite.
- **Réglages en listes** : les revenus et les charges fixes sont des listes de lignes (libellé, montant, jour du mois) au lieu de champs figés (`Réglages → Revenus, charges et épargne`). Le jour sert aux prévisions.
- **Noms des titulaires** (`Réglages → Profil`) : un ou plusieurs noms (ex. un conjoint). Chacun génère une règle « virement entre mes comptes » ; tout l'historique est reclassé.
- **Épargne prévue** : soit un montant fixe, soit **calculée automatiquement** à partir des investissements programmés et des objectifs.
- **Règles par défaut pour tout le monde** : 40+ familles d'enseignes nationales (supermarchés, fast-food, livraison, SNCF/RATP/Uber, Amazon/Fnac/Decathlon, pharmacies, salles de sport, streaming, opérateurs, énergie, courtiers et crypto, livrets, Lydia/Wero, salaires et aides). Tes commerçants personnels ne sont plus dans le code.
- **Nouvelles catégories par défaut** : génériques (« Restos & cafés », « Santé », « Logement & énergie »…), **sans objectif inventé**.
- **N'importe quelle banque** : choix du pays (12 pays) et recherche dans toute la liste Enable Banking, au lieu des deux boutons BNP / Revolut. Le type de compte (courant / épargne) vient de la banque.
- **Démo générique** : « Camille Martin », personne fictive, sur 6 mois. Elle ne remplit les réglages que sur une app vierge ; « Supprimer la démo » remet les réglages d'avant.
- **Nom de l'app** : « MyFinances » (constante `APP_NAME` dans `src/lib/app.ts`, facile à changer).

**Tes données V1 ne sont pas perdues** (`src/domain/settingsModel.ts`, testé) :
- tes anciens réglages sont **migrés automatiquement** à l'ouverture (salaire, APL et prime deviennent des lignes de revenus ; charges fixes et investissement sont repris ; ton nom devient un titulaire) ;
- tes catégories et règles personnelles déjà en base sont conservées ;
- une sauvegarde V1 se réimporte ;
- la base IndexedDB garde son nom, donc ton historique reste en place.

## 3. Gestion de toutes tes finances : patrimoine et placements

**Pourquoi.** Tu voulais suivre aussi tes investissements (Trade Republic, Bitstack), de façon personnalisable.

**Ce que j'ai vérifié avant de choisir.** Trade Republic et Bitstack n'ont **pas d'API publique** pour les particuliers. Bitstack ne propose qu'un export fiscal envoyé par e-mail. Je n'ai pas trouvé Trade Republic dans la liste Enable Banking, mais je n'ai pas pu interroger cette liste en réel faute de compte.

**Ce qui est en place :**
- **Onglet Patrimoine** : patrimoine net avec son historique (3 mois / 6 mois / 1 an), liquidités, placements avec plus-value, biens et dettes, répartition, placements, objectifs, comptes, et accès à la projection d'indépendance financière.
- **Placements** (n'importe quel établissement, avec des raccourcis Trade Republic, Bitstack, BoursoBank…) :
  - enveloppe (CTO, PEA, AV, PER, livret, crypto) ;
  - lignes avec quantité, **PRU (prix de revient moyen pondéré)**, valeur, plus-value latente, dividendes et frais ;
  - mouvements : achat, vente, dividende, frais.
- **Investissements programmés (DCA)** : mensuel, hebdomadaire ou toutes les 2 semaines (ex. plan d'épargne Trade Republic, Bitstack récurrent). Chaque échéance passée crée un achat au dernier cours connu, marqué « estimé » pour que tu le vérifies. Rien n'est jamais créé en double.
- **Cours automatiques via le relais** (`server/market.ts`) :
  - Yahoo Finance pour les ETF, actions et fonds, avec conversion en euros (y compris les cotations en pence) ;
  - CoinGecko pour la crypto ;
  - recherche par nom, ticker ou ISIN.

  Le téléphone ne contacte toujours **que ton domaine** (CSP `connect-src 'self'`) ; seuls des symboles partent vers ces services, jamais un montant. Les cours se mettent à jour au plus toutes les 6 h, ou à la demande. La saisie manuelle reste possible.
- **Historique du patrimoine** : une photo par jour. Avant la première, la courbe est **estimée** (solde reconstitué à rebours à partir des opérations + capital investi à chaque date), et c'est indiqué à l'écran.

## 4. Les 5 meilleures idées (recherche sur Internet), notées

**Méthode.** J'ai cherché ce que les comparatifs 2026 considèrent comme les fonctionnalités les plus utiles d'une app de finances (sources en bas). J'ai écarté ce que l'app faisait déjà (alertes, catégorisation automatique, synchro bancaire). J'ai noté **l'utilité pour toi** avant de coder, puis **le résultat** une fois implémenté, testé et vu à l'écran.

| # | Idée | Inspirée de | Utilité /10 | Résultat /10 |
|---|---|---|---|---|
| 1 | **Prévision de trésorerie** : ton solde jour par jour jusqu'à la paie (ou 30 / 90 jours), le point bas, les échéances à venir | Monarch (« cash flow forecasting »), Copilot | **9** | **7** |
| 2 | **Abonnements et récurrents détectés automatiquement**, avec les hausses de prix | Rocket Money, Cleo | **8** | **8** |
| 3 | **Objectifs d'épargne intégrés au budget** : montant, date, versement nécessaire, suivi par versements, par compte ou par placement | YNAB (« give every euro a job »), enveloppes Finary | **8** | **8** |
| 4 | **Patrimoine net unifié avec historique** : comptes, placements, biens, dettes | Finary, Monarch, Empower | **9** | **7** |
| 5 | **Indépendance financière (FIRE)** : dans combien de temps tes placements financent ton train de vie | « the path to financial independence » (freenance.io) | **6** | **8** |

### Pourquoi ces notes de résultat

1. **Prévision : 7/10.**
   - *Comment* : `src/domain/forecast.ts`. On part du solde des comptes courants. On ajoute les récurrences détectées, puis les lignes de tes réglages qui ont un jour et n'apparaissent pas déjà, puis tes plans d'investissement (sans double comptage). On retire le rythme moyen des dépenses courantes des 8 dernières semaines.
   - *Limites* : la dépense quotidienne est une moyenne plate (pas de fourchette haute / basse), et rien n'a été testé sur de vraies données bancaires.
2. **Récurrents : 8/10.**
   - *Comment* : `src/domain/recurring.ts`. Même commerçant (libellé nettoyé), intervalle régulier (hebdo → annuel), montant stable. Le système repère aussi une hausse ou une baisse de prix (le forfait de la démo passe de 15,99 € à 19,99 €). Tu peux confirmer, renommer ou écarter une récurrence (annulable).
   - *Limite* : un commerçant dont le libellé change à chaque fois n'est pas regroupé.
3. **Objectifs : 8/10.**
   - *Comment* : `goalProgress()`. Calcul du versement mensuel nécessaire et de la date d'arrivée au rythme prévu. L'objectif passe en or et une orbe s'allume quand il est atteint. Le versement prévu peut être retiré de l'enveloppe.
   - *Limite* : pas encore de rapprochement automatique avec un virement bancaire.
4. **Patrimoine : 7/10.**
   - *Comment* : `src/domain/wealth.ts`.
   - *Limites* : les placements Trade Republic et Bitstack se saisissent à la main (positions de départ, puis plans programmés). Yahoo Finance est une source non officielle qui peut changer sans prévenir ; dans ce cas, le cours repasse en saisie manuelle.
5. **FIRE : 8/10.**
   - *Comment* : `src/domain/fire.ts`. Rendement réel (rendement − inflation), intérêts composés mensuels, règle des 4 %. Les dépenses annuelles sont estimées sur tes 12 derniers mois. Simulation du versement mensuel, et effet de « +100 €/mois ».
   - *Limite* : c'est une projection en ligne droite, ce que l'écran dit clairement.

**Idées écartées** (utilité notée) : verrouillage par code et chiffrement local (7/10, prochaine étape logique), comptes partagés en couple (4/10), multi-devises (3/10), remboursement de dettes (3/10 pour toi aujourd'hui).

### Note globale

- **V1 : 6/10** pour une app « pour tout le monde » (excellente pour toi, inutilisable par un autre sans modifier le code).
- **V2 : 8/10.**
  - Ce qui la porte : design Lumen complet et cohérent dans 8 thèmes, personnalisation de bout en bout, budget + patrimoine + placements + prévisions au même endroit, données qui ne quittent pas le téléphone.
  - Ce qui manque pour 9 : un essai sur de vraies banques, l'import des relevés Trade Republic et Bitstack au lieu de la saisie, et un verrouillage de l'app.

## 5. Navigation

| Onglet | Rôle (un écran = un objectif) |
|---|---|
| **Aujourd'hui** | combien je peux dépenser aujourd'hui ; cloche des alertes et synchro en haut à droite |
| **Budget** | le cycle : enveloppe, courbe cumulée, catégories ; prévision et récurrents à un tap |
| **Opérations** | recherche, période (contrôle segmenté), filtres dans une feuille, file « à classer » |
| **Patrimoine** | patrimoine net, placements, objectifs, comptes, biens et dettes, indépendance financière |
| **Réglages** | profil, budget mensuel, catégories, règles, alertes, banques, apparence, données |

Les écrans poussés (détail d'un placement, prévisions, alertes, réglages…) masquent la barre d'onglets et ont une barre de verre avec retour. Leur action principale est fixée en bas, sous le pouce.

## 6. Limites connues

- **Toujours aucun essai avec une vraie banque** ni de déploiement réel : même situation qu'en V1, il faut ton compte Enable Banking.
- **Cours de bourse** : endpoints publics Yahoo Finance et CoinGecko, sans clé. Ils peuvent limiter le débit ou changer de format. Le code isole ces appels dans `server/market.ts`, et la saisie manuelle reste possible.
- **Taille du code JavaScript** : 685 Ko (222 Ko compressés), à cause de framer-motion. Ce n'est pas encore découpé par écran.
- **Emoji** : ils s'affichent en carrés sur les captures (pas de police emoji dans le Chrome de WSL). Sur téléphone, ils s'affichent normalement.
- **Historique Git** : les étapes ont été regroupées en 3 commits (design system ; personnalisation + patrimoine + idées + écrans ; documentation), car elles se touchaient toutes.
